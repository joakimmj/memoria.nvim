1. INTRODUCTION                                     *memoria-introduction*

memoria.nvim keeps notes as plain markdown. A brain is a folder of notes; an
engram is one note in it. Files stay readable without the plugin.

Nothing is mapped by default.

==============================================================================
2. REQUIREMENTS                                     *memoria-requirements*

Neovim 0.10 or later, and md-drafting.nvim with its `api` table.
`setup()` checks for it and stops with an error when it is missing.

==============================================================================
3. CONFIGURATION                                          *memoria-config*

Three tiers, later over earlier: built-in defaults, `setup()`, and the
brain's own `.mia_dna.json`. Maps merge by key; lists replace wholesale.

                                                           *memoria-config-null*
A missing key follows the tier above. `null` in JSON, or `vim.NIL` in
`setup()`, removes it instead:

- an entry in `synapses` stays removed, e.g. `{ "synapses": { "up": null } }`
  gives the brain no `up` field;
- any other setting goes back to its built-in default, skipping the value
  from `setup()`.
Every value below is the default: >lua

    require("memoria").setup({
      -- Create the :Mia* user commands.
      add_commands = true,

      engrams = {
        -- Tokens: YYYY, YY, MM, DD, HH, mm, ss.
        date_format = "YYYYMMDD",
        filename = {
          -- "date" or "none".
          prefix = "date",
          separator = "_",
        },
        -- Prose under the generated header. %cursor% marks where typing
        -- starts; %title% and %date% are expanded.
        content_template = "# %title%\n\n%cursor%",
        -- Checkbox markers the atlas indexes, by state. Replaces the
        -- default rather than adding to it.
        task_markers = {
          not_done = { "[ ]" },
          done = { "[x]", "[X]" },
        },
      },

      -- Engram fields go in the SYNAPSES block, concept fields in
      -- frontmatter. Both are written sorted by name.
      synapses = {
        -- target: "engram" or "concept". show_empty writes the field
        -- even with no values. inverse: the engram field kept in sync on
        -- the other side. list = false: one value, replaced on add.
        up = { target = "engram", inverse = "down", list = true, show_empty = true },
        down = { target = "engram", inverse = "up", list = true, show_empty = true },
        tags = { target = "concept" },
      },
    })
<
                                                      *memoria-mia_dna.json*
A brain's `.mia_dna.json` holds only what differs, with the same keys: >json

    { "engrams": { "filename": { "prefix": "none" } } }
<
|:MiaBrainConfig| opens the file, writing `{}` first when the brain has none.
Keys left out follow `setup()` and the defaults, so an override keeps working
when those change — write only what this brain needs. It cannot set
`add_commands`. JSON has no comments. An unreadable or invalid file is
reported and skipped.

4. BRAINS                                                 *memoria-brains*

Brains are registered per machine in `stdpath("data")/memoria/brains.json`,
with absolute locations. Deregistering never touches files.

The active brain lives for the session only. When a brain is not named, it
is resolved in this order:

    1. the brain holding the current buffer's file
    2. the active brain
    3. the only registered brain, when there is exactly one
    4. a picker over registered brains

So the active brain is not always the one acted on. |:MiaBrainList| marks
both: `>` the brain holding the current buffer, which wins, and `*` the active
one. Prompts name their brain, e.g. >

    (work) Engram title:
<
A brain that *is* named must exist: an unknown name is an error, never the
picker.

==============================================================================
5. ENGRAMS                                               *memoria-engrams*

`add_engram` prompts for a title. The title is written as typed into
%title%; the filename uses its slug: >

    Note about Java
    20260801_note_about_java.md      prefix = "date"
    note_about_java.md               prefix = "none"
<
The slug is lowercased, whitespace becomes `filename.separator`, and
characters no filesystem allows (/ \ : * ? " < > |) are dropped. When the file
already exists, or nothing usable is left, |:MiaEngramAdd| asks again with the
title filled in and the reason in the prompt.

The file gets a generated header, then the content template: >markdown

    ---
    tags: []
    ---
    <!-- SYNAPSES -->
    - **down:**
    - **up:**
    ***
    <!-- /SYNAPSES -->

    # Note about Java
<
The frontmatter is left out when no `synapses` field has target "concept",
and the SYNAPSES block when none would show a line. A brain with every field
removed (|memoria-config-null|) gets plain markdown. A blank line separates
the header from the template, and is left out with the header.

The buffer opens with the cursor at %cursor%.

==============================================================================
6. SYNAPSES                                             *memoria-synapses*

|:MiaSynapseAdd| links the current engram to another through an engram field,
and writes the field's `inverse` on the other one: >markdown

    <!-- SYNAPSES -->
    - **down:**
    - **up:** [20260801_project-x](20260801_project-x.md)
    ***
    <!-- /SYNAPSES -->
<
Link text is the filename without `.md`. Adding a link that is already there
changes nothing, so adding it again repairs a synapse with only one side. A
field with `list = false` gives up its old value, and that engram loses its
inverse back. A field without an `inverse` is written on one side only.

A field line the config does not name, e.g. one added by hand, is kept.
Frontmatter that cannot be read stops the write, and neither file changes.
An engram open in a buffer is written through the buffer and saved.

==============================================================================
7. ATLAS                                                   *memoria-atlas*

Each brain keeps a derived index in `.mia_atlas.json`: per engram its title,
synapses, linked engrams, concept fields (e.g. `tags`) and tasks, plus
backlinks and which engrams name each concept. It can be deleted at any time.

The atlas brings itself up to date whenever memoria reads it: new and changed
engrams are parsed again, deleted ones dropped. Edits made outside Neovim are
picked up the same way.

|:MiaAtlasRebuild| builds it from scratch and puts what is wrong in the
quickfix list:

- a synapse or link to an engram that does not exist;
- a synapse whose inverse is missing on the other engram;
- frontmatter that cannot be read.

With `!` it first writes every missing inverse, and regenerates each existing
SYNAPSES block from config, adding lines for fields configured since.

8. COMMANDS                                             *memoria-commands*

These global commands are created unless `add_commands = false`.

                                                              *:MiaBrainAdd*
:MiaBrainAdd {path} [name]  Register {path} as a brain, creating it if
                            missing. [name] defaults to the folder name.
                                                       *:MiaBrainDeregister*
:MiaBrainDeregister [name]  Remove a brain from the registry; picked when
                            not named
                                                             *:MiaBrainList*
:MiaBrainList               List brains; `*` marks the active one, `>` the
                            one holding the current buffer, "(config)" a
                            brain with its own .mia_dna.json, ⚠ a missing
                            folder
                                                           *:MiaBrainSwitch*
:MiaBrainSwitch [name]      Set the active brain; picked when not named
                                                           *:MiaBrainConfig*
:MiaBrainConfig [brain]     Open the brain's .mia_dna.json, creating an
                            empty one when it has none
                                                             *:MiaEngramAdd*
:MiaEngramAdd [brain]       Ask for a title, create an engram and open it,
                            asking again when the title cannot be a filename
                                                            *:MiaSynapseAdd*
:MiaSynapseAdd [field]      Link the current engram to another, picked,
                            through [field] (picked when not given)
                                                          *:MiaAtlasRebuild*
:MiaAtlasRebuild[!] [brain] Rebuild the atlas and list problems in the
                            quickfix list; with ! repair what can be

9. API                                                       *memoria-api*

    local memoria = require("memoria")

    memoria.setup({opts})
        Check the dependency, store options, create commands. Returns true,
        or nil and why not.

Two layers. `memoria.{feature}` is what the |memoria-commands| call: it asks
for what you left out, opens what needs opening, and reports what went wrong —
bind these to a keymap. `memoria.core.{feature}` is the same feature without
any of that: it asks nothing, opens nothing, and answers a result, or nil and
an error naming no brain.

    memoria.brain.add({path}, {name})
        Register a folder as a brain, reporting the result.
    memoria.brain.deregister({name})
        Remove a brain from the registry; picked when not named.
    memoria.brain.switch({name})
        Set the active brain; picked when not named.
    memoria.brain.open_config({name})
        Open a brain's .mia_dna.json, creating "{}" when it has none.
    memoria.brain.print_list()
        Echo every brain, see |:MiaBrainList|.
    memoria.brain.pick({run})
        Pick a registered brain and pass it to {run}.
    memoria.brain.resolve({name}, {run})
        Resolve a brain (see |memoria-brains|) and pass it to {run}, with the
        picker as the last step.
    memoria.brain.choose({name}, {run})
        The picker straight away when {name} is empty, for choosing a brain
        rather than acting in one.

    memoria.engram.add_engram({brain}, {opts})
        Ask for a title, create the engram and open it at its cursor, asking
        again when the title cannot be a filename.

    memoria.synapse.add_synapse({opts})
        Link the current engram to another. {opts}.source (path, default: the
        current buffer), {opts}.field and {opts}.target are asked for when
        left out.

    memoria.atlas.rebuild_atlas({brain}, {opts})
        Rebuild and report into the quickfix list. {opts}.fix repairs missing
        inverses and backfills SYNAPSES blocks first.

Every function below answers a result, or nil and an error.

    memoria.core.brain.add({path}, {name})
        Register a folder as a brain. Returns the brain.
    memoria.core.brain.deregister({name})
        Remove a brain from the registry. Files are never touched.
    memoria.core.brain.switch({name})
        Set the active brain. Returns it.
    memoria.core.brain.resolve({name})
        The brain to act in, see |memoria-brains|. The picker is the view's,
        so an unnamed brain that resolves to nothing is an error here.
    memoria.core.brain.ensure_config({brain})
        A brain's .mia_dna.json, written as "{}" when it has none. Returns
        its path.
    memoria.core.brain.active()
        The active brain, or nil.
    memoria.core.brain.current()
        The brain commands would act on, and why, or nil.
    memoria.core.brain.containing({file})
        The brain whose folder holds {file}, or nil.
    memoria.core.brain.get({name})
        A registered brain, or nil.
    memoria.core.brain.list()
        Every brain, sorted by name.
    memoria.core.brain.names()
        Every brain name, sorted.

    memoria.core.engram.add_engram({brain}, {opts})
        Create an engram, opening nothing. {opts}.title is required,
        {opts}.fields fills the frontmatter, {opts}.body lands at %cursor%.
        Returns `{ path, cursor }`, or nil, an error, and a code:
        "empty_slug", "collision" or "prefix" (see |memoria-engrams|).
    memoria.core.engram.header({cfg}, {fields})
        The generated header for a config, with {fields}' values in it.
    memoria.core.engram.filename({cfg}, {slug}, {time})
        The filename a slug gets under the configured prefix.
    memoria.core.engram.slugify({title}, {separator})
        The filename-safe slug of a title.

    memoria.core.synapse.add_synapse({opts})
        Link two engrams and refresh the atlas. {opts}.source (path),
        {opts}.field and {opts}.target are all required. Returns what it
        linked.
    memoria.core.synapse.connect({brain}, {source}, {target}, {field})
        Link two engrams by filename, both sides.
    memoria.core.synapse.locate({path})
        The brain and filename of an engram path, or why it is not one.

    memoria.core.atlas.refresh({brain}, {opts})
        Bring the brain's atlas up to date and return it. {opts}.full parses
        every engram again.
    memoria.core.atlas.rebuild_atlas({brain}, {opts})
        Rebuild from scratch and check it. Returns `{ atlas, problems }`;
        {opts}.fix repairs missing inverses and backfills SYNAPSES blocks
        first.
    memoria.core.atlas.locate_problems({brain}, {problems})
        The same problems, each with the file and row it sits on.
    memoria.core.atlas.check({atlas}, {cfg})
        Everything wrong with a brain's links, each with a kind.

A brain is `{ name, location }`.
